## 本轮已修复

- **首页减少动态效果模式水合错误**：PressTape 原来服务端渲染滚动带，客户端 render 根据 matchMedia 返回 null，触发 React 重新生成。现在固定两端 DOM，用 CSS 控制可见性，并新增真实 hydration 回归。
- **遮挡文字只能鼠标悬停**：Redacted 改原生按钮，Enter、Space 和触摸都能切换显示，状态可被辅助技术读取。
- **手机/平板进度框盖住正文**：ReadingFolio 在 1280px 以下改为顶部 2px 进度线，文字保留给辅助技术；宽屏继续在侧边显示页码，不拦截点击。
- **Lab 横向展览没有有效滚动区间**：改为测量实际容器，并增加与横向溢出对应的纵向距离；ResizeObserver 处理容器/内容变化，减少动态效果设置可实时切换。实测桌面横向连续移动至 −557px，手机至 −502px。
- **旧文章数值断言错误**：梯度文章原称 1e-6 会在 float32 中直接变零；用标准库打包/解包验证其值约为 9.99999997e-7，修正文案，区分梯度很小与权重更新被舍入。
- **分享图仍有虚构剧情身份**：OG 模板原有 1954-PYE 与1954，改为 Python / Go / AI infrastructure 和 OA。

## 阅读与个人品牌建议

这些是设计建议，不是已实现功能：

1. 长技术文章增加章节目录和可复制的段落锚点。目前 h2 没有 id，读者难以直达 KV Cache 或路由成本等段落。目录在手机折叠，宽屏放在正文边栏。
2. 顶部作者名应保持稳定可读。作者卡目前用 AnagramText，普通网络加载时先出现乱码，无 JavaScript 时永久停留在乱码。可以把解码效果留给 Lab，作者署名直接显示文字。
3. 保留一次有辨识度的封面动效，减少阅读操作的等待。当前 Veil 每次内部导航先等待 550ms，再花 550ms 揭幕；建议文章间导航缩短过渡。
4. 三篇 LLM 图当前在正文较靠前的位置，手机上图中文字缩得很小。优先通过紧邻机制段落、精简图注和可展开高清图提升理解，不急于增加装饰图。
5. 新增“下一篇/相关主题”比继续添加重复介绍区块更有利于连续阅读；依据已有 tags 生成，并排除当前文章和草稿。

## 性能采样方法与限制

冷缓存、本地 gzip 静态构建，Chrome 390×844，CDP 设置 150ms 延迟、200,000 B/s 下载、4× CPU 节流。每页等待资源加载完成后再观察 2 秒，记录 PerformanceObserver。原始数据和复现脚本在 `output/audit/baseline.json` 与 `output/audit/deep-check.mjs`。

| 页面 | 本次 LCP 观察值 | 资源传输体积，不含主文档 | 非交互布局偏移总和 |
| --- | ---: | ---: | ---: |
| 首页 | 604ms | 306,421 B | 0 |
| Attention | 600ms | 2,991,304 B | 0.00454 |
| 文章列表 | 584ms | 326,443 B | 0 |
| 关于页 | 584ms | 259,549 B | 0 |

这是单机短时实验，不代表公网用户分位数。偏移值是观察窗口内求和，不是完整会话窗口 CLS 算法；没有采集真实用户 INP，也不把这些数字换算成 Lighthouse 分数。首屏文字很早出现与配图传输很慢可以同时成立。

度量定义及实验限制依据 [Web Vitals 官方说明](https://web.dev/articles/vitals)；[Lighthouse 评分机制](https://developer.chrome.com/docs/lighthouse/performance/performance-scoring)也说明评分受环境影响。

## 建议推进顺序

1. **发布完整性**：公开内容清单、草稿隔离、404 和正式域名。
2. **加载与阅读**：图片响应式派生、正文按需加载、章节目录和相关主题。
3. **动效收尾**：补齐 Lab 剩余减少动态效果覆盖，收敛文章导航动画。
